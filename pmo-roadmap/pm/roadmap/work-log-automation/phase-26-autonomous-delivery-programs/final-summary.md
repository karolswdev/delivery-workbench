**Status:** complete.

## Delivered value

run a governed local delivery organization across an exact roadmap scope.

verifiers, critics, judges, meta-verifiers, and architects; finite repair,
debate, audit, escalation, and phase-gate routes remain explainable and
replayable. Mechanical facts, governed judgments, council decisions, dissent,
and obligations retain distinct types and provenance.

One immutable, expiring, revocable program grant names the resolved execution
roster, capabilities, budgets, scope, repository facts, and permanent
exclusions. The embedded conductor takes one replay-derived act at a time.
Exact delivery claims separately govern evidence, integration, certification,
commit, fast-forward push, obligation disposition, and roadmap transitions.
CLI, MCP, HTTP, Workbench, SSE, notifications, and bounded streams project the
same ledger rather than creating another scheduler or authority path.

The Python-floor wheel exam closes the proof: one continuous grant delivers
three stories across two phases, including an independent fail→repair→pass
route, a dissent-preserving council, a carried non-blocking obligation, a full
meta-audit, architect gates, three commits/pushes, and planted crash recovery.
A separate fresh consumer proves that ordinary Delivery Workbench and bounded
orchestration remain complete, dormant modes with no ambient program machinery.

## Red capture that improved the product

The full installed path found one genuine driver bug. Git's default untracked
status summary returned a nested candidate as `src/`, but the binary diff and
declared scope named `src/feature/candidate.py`. That mismatch caused a correct
isolated implementation to fail closed at collection. The driver now requests
file-level untracked status with `--untracked-files=all`; a focused unit test
pins the exact path. The acceptance exam stayed unchanged at that boundary and
passed only after the product was corrected.

The first Linux package run then found a fixture-only portability assumption:
the runner's bare-repository default still advertised `master`, while the exam
pushed `main`. Refusal clones therefore checked out no program. The exam now
sets the bare remote's default branch explicitly and asserts each clone's
program policy exists. Re-running the complete Python 3.9 package smoke with a
forced `init.defaultBranch=master` passed, so the proof no longer depends on a
developer's Git configuration.

That replacement run made the repaired package lane green and independently
found a macOS timing flaw in the public-surface concurrency test. Its workers
performed two full pure preview replays before a fixed barrier, allowing slow
runner scheduling to time out before the execution race began. The stabilized
harness brings both workers to an immediate rendezvous and returns the same
already-reviewed preview to each; it changes no runtime path and more exactly
tests that one frontier is consumed once while the competing caller is refused
as stale.
The repaired seam passed 20 consecutive macOS/Python 3.14.6 repetitions; the
old seam reproduced the timeout on repetition two under the same stress.
The complete post-repair core then passed 473/473 tests on both Python 3.14.6
and the declared Python 3.9 floor while the suites ran concurrently.

## Deterministic proof versus live execution

The mandatory oracle injects deterministic fixture behavior behind the shipped
Claude/Sonnet-like `claude-exec` and pi/OpenRouter/Kimi-like `pi-exec`
contracts. It proves compilation, resolved execution fingerprints,
independence, scheduling, authority, receipts, recovery, delivery, and public
surface parity without credentials, network dependence, or variable model
output.

No explicit authenticated live-agent specimen was requested. That optional
specimen is **not run**, not passed. Phase completion therefore makes no claim
about an untested provider alias, model revision, hosted execution, or general
live-model quality. Homebrew remains an honest environment abstention owned by
its clean-machine macOS lane.

## Authority decisions carried forward

- Autonomous programs are optional; no policy plus no grant is the normal
  healthy default.
- Policy describes possibility. Only a separate exact finite grant is
  authority.
- Deterministic roadmap selection and assignment—not model ranking—choose work
  and seats.
- Every autonomous story requires independent verification; mechanical facts
  can only come from registered check/rail adapters.
- Councils preserve dissent and disclose whether a rule, preassigned decider
  seat, or external checkpoint owns the outcome.
- Crash recovery reconciles claims and receipts before retry; uncertainty is a
  stop, never permission to repeat a destructive act.
- Commit and push are separate named capabilities. Merge, release, deploy,
  publication, hosted authority, and conflict resolution remain excluded.

## Next phase direction

The next phase is a plain-language application-layer redesign. Internal code,
machine contracts, architecture, and an explicit audit view may keep exact
terms such as grant, ledger, preview token, content boundary, and
certification. Everyday Program Studio, team and council setup, live operation,
help, errors, onboarding, and product documentation must not require people to
speak those terms.

That phase should establish one clear product vocabulary for the delivery
plan, team, work, review, decision, blocker, permission, progress, cost, and
next step; apply it consistently across every user-facing surface; and test
whole tasks with people-readable acceptance examples. This is product and
information design, not a find-and-replace pass or a second set of runtime
semantics.

Phase 26 still stops before landing or release. No version bump, merge, tag,
GitHub release, PyPI publication, Homebrew formula update, deployment, or
cross-repository authority is implied by this closeout; those remain separate
owner decisions.
