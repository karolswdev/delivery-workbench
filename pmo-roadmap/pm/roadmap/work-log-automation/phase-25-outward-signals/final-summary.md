# Phase 25 Final Summary

**Status:** complete.
**Date:** 2026-07-22.

## Delivered value

Delivery Workbench can hear the world outside a bounded orchestration run and,
only under a score-declared and separately granted standing rule, route the
right agent back to declared work. GitHub/fixture SCM facts, CI and review
status, merge state, external commits and driver activity become deduplicated,
content-safe, hash-chained facts. Observation starts nothing and carries no
forge, repository, agent, certification or integration authority.

The granted nudge engine combines four independently visible checks: a score
rule, exact standing grant, receptive driver state and an at-most-once ledger
receipt. Nudges are structured facts rather than commands, obey finite budgets,
never inject into blocked/unknown sessions and exhaust into a recorded stop.
Clean operator pushes can rebind an exact still-live run without turning the
observer into an actor.

Human decisions are now durable typed request documents. Checkpoint requests,
correlations, response schemas, age/origin, restart republish, decisions,
refusals and expiry derive from the run ledger; CLI, MCP, HTTP, Workbench and
Telegram cross the same exact-token local request boundary. Notifications and
the SSE live tail are replayable read models, not authority channels.

The neutral driver seam now includes a least-privilege non-interactive Claude
Code adapter with harness-owned authentication, version-pinned discovery,
closed tools, scrubbed environment and honest activity. Deterministic fixtures
remain the CI oracle; a separate authenticated live specimen proved the real
driver and nudge round-trip.

## Outcome against exit criteria

1. `delivery-workbench-signal@1` defines outward facts, derived status,
   activity/receptivity, nudge/receipt rules, typed requests, privacy and a
   fail-check threat table.
2. The authority-free observer and semantic fact store expose equivalent reads
   across CLI/MCP/HTTP and provably start or mutate nothing outside their own
   append-only observation store.
3. Driver activity is an exact six-state vocabulary with conformance checks;
   `blocked` and `unknown` are never receptive.
4. Standing nudges require score + grant + receptivity + unused exact signal,
   remain at-most-once across restart and stop at finite budget exhaustion.
5. SSE replays verified run/signal ledger suffixes exactly from cursors and the
   Workbench Run view consumes it without gaining a mutation route.
6. Notifications persist unread/ack/delivery attempts and the per-person
   Telegram surface carries only typed correlations/previews—never local tokens
   or apply commands.
7. The Claude Code adapter passed conformance and an authenticated two-attempt
   live nudge specimen with no model output in the CI oracle.
8. Outstanding requests survive pause/restart, republish once per generation,
   refuse stale/wrong/expired responses and clean up terminal crash prefixes.
9. The fresh-wheel exit exam composed push, rebind, CI/review signals, two
   nudges, repair, named approval, crash/restart, request republish/refusal/
   decision, notification delivery/ack, stream replay, revocation and every new
   refusal while preserving operator-only certification and integration.

## Red captures that improved the product

- A sanctioned operator push originally made a still-exact run stale forever;
  closed `external_commit_observed` facts now rebind only clean same-repository,
  same-branch fast-forwards with an unchanged in-progress story.
- A terminal approval stayed pending after terminal handoff, preventing a
  nudge-woken run from handing back a second time; terminal checkpoints are now
  historical handoffs rather than outstanding requests.
- A failure-activated repair started by a nudge became dormant after failing;
  completed nudge attempts now execute their declared retry/route/approval/
  pause/abort policy.

Each finding has a focused regression in the 338-test core suite.

## Authority decisions carried forward

- Observation is never action; nudge authority lives in a separate finite
  grant and every delivery is score-declared and receipted.
- Driver state is reported capability, not guessed liveness. Unknown and
  blocked remain non-receptive even for manual injection.
- Request identity and lifecycle derive from the authoritative ledger rather
  than a crash-prone second store.
- Typed phone decisions are documents crossing the local exact-token core;
  transport possession alone is not authority.
- Certification, commit, push, merge, release and deploy were not inherited by
  Phase-25 work/nudge authority.
