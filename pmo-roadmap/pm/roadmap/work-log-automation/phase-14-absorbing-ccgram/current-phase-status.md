# Phase 14 - The Absorption: ccgram, transmuted

**Last updated:** 2026-07-04.

## Goal

Absorb and re-interpret ccgram's operational excellence under the consent spine: hook-driven push, the message layer, topics-as-projects, the driver's craft, guarded file sending.

## Scope

- **In:** Absorb and transmute alexei-led/ccgram (v4.3.5, MIT,
  lineage six-ddc — studied in full 2026-07-04) into the Telegram
  interface: hook-driven instant push with a dw-native hook seam,
  the hardened message layer (entities, FIFO queue, edit-in-place),
  topics-as-projects with freely flowing conversation inside a
  bound session (owner decision 2026-07-04: consent gates entry,
  not every utterance), the driver's TUI craft + live view +
  toolbar + recovery, and /send behind seven locks. Ideas
  re-interpreted under the pairing/binding/gate spine; attribution
  explicit; any ported code carries the MIT notice.
- **Out:** SDK-wrapping agents (the multiplexer stays the source
  of truth — their thesis, kept); user-ID allowlist auth;
  NL→shell synthesis; multi-owner access; inbound file uploads.

## Exit criteria (evidence required)

- [ ] The absorption map exists and every treated idea is marked
  absorb/transmute/refuse with citations (WLA-14-01).
- [ ] A blocked agent reaches the phone in ~1 s via the dw hook
  seam, fixture- and live-proven (WLA-14-02).
- [ ] A multi-turn typed conversation flows through a bound topic
  with zero per-message taps, and revocation stops it instantly
  (WLA-14-04).
- [ ] The message layer survives a burst ordered, merged, and
  formatted with no escaping logic (WLA-14-03).
- [ ] /send delivers clean files directly and refuses each planted
  hazard by lock name (WLA-14-06).
- [ ] The live day runs end-to-end with screenshots in evidence
  and the crown case refused from a topic (WLA-14-07).
